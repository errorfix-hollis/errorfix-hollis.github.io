npm & Node.js errors

  • Error [ERR_MODULE_NOT_FOUND]: Cannot find moduleIn ES modules, Node needs the full file path including the .js extension. Add the extension to your import or install the missing package.
  • Error [ERR_REQUIRE_ESM]: require() of ES Module not supportedYour CommonJS code calls `require()` on a package that is ESM-only (node-fetch 3, chalk 5, nanoid 4, got 12, p-limit 4 and others). Use `import`, a dynamic `import()`, the last CommonJS version of the package, or Node 22.12+ which can require most ES modules.
  • Error: Cannot find moduleNode can't find a package or file you required. Install the dependency, fix the path, or check you're running from the right folder.
  • Error: ENOSPC: System limit for number of file watchers reachedOn Linux, your dev server (webpack, Vite, Jest, nodemon, VS Code) ran out of inotify watches. It's not about disk space — raise fs.inotify.max_user_watches or watch fewer files.
  • Error: error:0308010C:digital envelope routines::unsupportedAn old webpack (often via react-scripts 4 or Vue CLI 4) uses the MD4 hash, which OpenSSL 3 in Node 17+ disables. Upgrade webpack/react-scripts, or use the legacy OpenSSL provider.
  • Error: listen EADDRINUSE: address already in use :::3000Another process (often an old copy of your own dev server) is already listening on that port, so Node can't bind to it. Stop that process or use a different port.
  • Error: unable to get local issuer certificate (UNABLE_TO_GET_ISSUER_CERT_LOCALLY)Node.js could not build a trust chain for the server's TLS certificate because the issuing CA is not in Node's CA store. Almost always a corporate proxy or antivirus that re-signs HTTPS traffic with its own root certificate.
  • Error: unable to verify the first certificate (UNABLE_TO_VERIFY_LEAF_SIGNATURE)Node.js got a TLS certificate it can't chain to a trusted root. Usually the server doesn't send its intermediate certificate, or a corporate proxy/internal CA signed it and Node doesn't trust that CA.
  • FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memoryNode's V8 engine ran out of the heap memory it is allowed to use. Common during big webpack/Vite/Next.js/TypeScript builds. Raise the limit with --max-old-space-size or reduce memory usage.
  • gyp ERR! find PythonA package with a native C/C++ addon (bcrypt, sqlite3, node-sass, canvas...) is being compiled with node-gyp, which needs Python and a C++ compiler, and it couldn't find a usable Python.
  • npm ERR! code E404 - Not Foundnpm couldn't find the package (or version) in the registry it asked. Typo in the name, a private/scoped package without auth, a wrong registry in .npmrc, or a version that was never published.
  • npm ERR! code EACCESnpm can't write to the global install folder. Don't use sudo; point npm's global prefix at your home directory or use a Node version manager.
  • npm ERR! code EINTEGRITYThe tarball npm downloaded (or found in its cache) doesn't match the integrity hash recorded in package-lock.json. Usually a corrupted cache, a lock file created against a different registry, or a proxy altering downloads.
  • npm ERR! code ELIFECYCLEAn npm script exited with an error. ELIFECYCLE itself is not the problem — the real error is printed above it.
  • npm ERR! code ENOTEMPTYnpm tried to rename a folder inside node_modules (or the global prefix) but the target was not empty, usually leftovers from an interrupted install. Deleting node_modules and reinstalling fixes it.
  • npm ERR! code EPERM operation not permittedThe operating system refused a file operation (rename, unlink, mkdir) npm needed. On Windows it's almost always a file locked by a running process, antivirus or an editor; elsewhere it's ownership or a read-only/synced folder.
  • npm ERR! code ERESOLVE unable to resolve dependency treeA package's peer dependency doesn't match the version you have installed. Upgrade the package, or install with --legacy-peer-deps.
  • npm ERR! code ERR_SOCKET_TIMEOUTnpm opened a connection to the registry but no data arrived within the timeout. Causes: slow or flaky network, a proxy or VPN, IPv6 problems, too many parallel downloads, or a slow mirror.
  • npm ERR! code ETIMEDOUTnpm could not reach the registry in time. The usual causes are a corporate proxy, a broken IPv6 route, a wrong registry URL or a flaky connection; the same fixes apply to ECONNRESET and ERR_SOCKET_TIMEOUT.
  • npm ERR! code SELF_SIGNED_CERT_IN_CHAINnpm's TLS check found a certificate in the chain that isn't signed by a CA Node trusts. Almost always a corporate proxy or antivirus intercepting HTTPS with its own root certificate.
  • npm ERR! enoent Could not read package.jsonYou ran npm in a folder without a package.json. cd into your project, or create one with npm init.
  • npm WARN deprecated <package>@<version>: <message>A warning, not an error: the package author marked that version as deprecated on the registry. Your install still succeeded. Most of these come from transitive dependencies you don't control directly.
  • npx: command not foundThe shell can't find the npx executable. Node.js isn't installed, was installed without npm (some distro packages), or its bin directory isn't on your PATH (common with nvm in new shells, CI and IDE terminals).
  • TypeError: fetch failedNode's built-in fetch (undici) couldn't complete the request at the network level. The real reason is in the error's cause: ECONNREFUSED, ENOTFOUND, a timeout, a TLS certificate error, or localhost resolving to IPv6.
